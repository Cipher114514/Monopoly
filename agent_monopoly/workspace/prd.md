# 产品需求文档

## 1. 项目概述

### 1.1 项目名称
在线大富翁游戏

### 1.2 项目目标
本课程作业要达成的学习目标和功能目标：
- 学习React前端框架和Node.js后端开发
- 掌握Socket.io实时通信技术
- 实现一个简化版的大富翁游戏核心玩法
- 展示多人实时对战的基本架构
- 完成基本的游戏流程和交互功能

### 1.3 适用场景
- 课程作业展示和演示
- 2-6人同时在线的小型游戏聚会
- 学习实时多人游戏开发的参考案例

### 2.2 核心功能详细说明

#### F01: 用户系统
- **功能描述**: 实现用户的注册、登录和退出功能
- **用户操作**: 用户输入用户名和密码进行注册/登录，点击退出按钮
- **系统响应**: 验证用户信息，创建会话，记录登录状态
- **实现要点**: 使用简单的本地存储或轻量级数据库，不实现复杂的安全机制

#### F02: 房间系统
- **功能描述**: 创建游戏房间、加入已有房间、显示房间列表
- **用户操作**: 创建房间并设置房间信息，从列表中选择房间加入
- **系统响应**: 创建房间实例，管理房间状态，更新房间列表
- **实现要点**: 房间最多支持6人，房间满员后自动关闭加入功能

#### F03: 游戏初始化
- **功能描述**: 初始化游戏棋盘、玩家位置和初始资金
- **用户操作**: 房间内所有玩家准备后，由房主开始游戏
- **系统响应**: 创建棋盘数据，设置玩家初始位置和资金，随机分配棋子
- **实现要点**: 使用简化版棋盘，包含基本地产和特殊格子

#### F04: 掷骰子移动
- **功能描述**: 玩家轮流掷骰子，按照点数移动棋子
- **用户操作**: 当前玩家点击掷骰子按钮
- **系统响应**: 生成1-6随机数，更新玩家位置，触发相应格子事件
- **实现要点**: 实现骰子动画效果，移动过程中经过的格子触发相应事件

#### F05: 地产系统
- **功能描述**: 购买无人地产、支付过路费
- **用户操作**: 当玩家落在无人地产上时选择购买，落在他人地产上时支付过路费
- **系统响应**: 处理购买交易，扣除/增加玩家资金，更新地产所有权
- **实现要点**: 简化地产规则，不实现复杂的地组效果

#### F06: 基本游戏流程
- **功能描述**: 实现玩家轮流进行游戏，判定破产和胜负
- **用户操作**: 玩家完成自己的回合后点击结束回合
- **系统响应**: 切换到下一个玩家，检查破产条件，判定游戏结束
- **实现要点**: 当有玩家破产时，其资产由其他玩家分配，最后剩一名玩家时游戏结束

#### F07: 机会命运卡牌
- **功能描述**: 玩家落在特定格子时抽取卡牌并执行效果
- **用户操作**: 玩家抽取卡牌后查看效果
- **系统响应**: 随机抽取卡牌，执行卡牌效果（如移动、罚款、奖励等）
- **实现要点**: 实现简化的卡牌系统，包含基本效果

#### F08: 房屋建设
- **功能描述**: 玩家可以在自己的地产上建设房屋
- **用户操作**: 玩家点击自己的地产选择建设房屋
- **系统响应**: 扣除建设费用，增加地产上的房屋数量，提高过路费
- **实现要点**: 简化建设规则，每块地产最多建设1-2个房屋

#### F09: 游戏状态同步
- **功能描述**: 实时同步游戏状态给所有玩家
- **用户操作**: 玩家进行游戏操作
- **系统响应**: 通过Socket.io广播游戏状态更新
- **实现要点**: 实现服务器权威架构，防止客户端作弊

#### F10: 聊天系统
- **功能描述**: 玩家间可以进行简单文字聊天
- **用户操作**: 输入聊天内容并发送
- **系统响应**: 将聊天内容广播给房间内所有玩家
- **实现要点**: 简单的文本聊天，不实现表情或图片

## 3. 系统约束

### 3.1 技术栈（已知）
- 前端: React + Socket.io-client
- 后端: Node.js + Express + Socket.io
- 数据存储: 本地文件存储或轻量级数据库（如SQLite）
- 实时通信: Socket.io

### 3.2 开发约束
- 开发时间: 短期（2-3周）
- 人力: Agent自动生成代码 + 人工调试优化
- 数据存储: 简单的JSON文件或轻量级数据库
- 代码规模: 每个组件控制在合理范围内，避免过度复杂

### 3.3 不包含的功能
明确列出**本作业不实现**的功能：
- 复杂的地组效果和垄断奖励
- 拍卖系统
- 交易系统（玩家间直接交易）
- 游戏回放功能
- 移动端适配
- 用户头像和个性化设置
- 复杂的统计数据和历史记录
- AI单人游戏模式
- 音效和复杂动画
- 防作弊机制（基础架构外）
- 多语言支持
- 支付系统

## 5. 用户界面要求

### 5.1 页面结构
- **登录页面**: 用户名和密码输入，注册和登录按钮
- **大厅页面**: 房间列表，创建房间按钮
- **房间页面**: 显示房间内玩家，聊天区域，准备/开始按钮
- **游戏页面**: 棋盘显示，玩家信息面板，操作按钮（掷骰子、购买、建设等），聊天区域

### 5.2 交互流程
1. 用户注册/登录进入游戏大厅
2. 创建房间或加入现有房间
3. 房间内玩家准备后，房主开始游戏
4. 玩家轮流掷骰子移动
5. 根据所在格子触发相应事件（购买地产、支付过路费、抽卡等）
6. 玩家可以建设自己的地产
7. 当有玩家破产时，游戏继续
8. 最后剩一名玩家时，游戏结束并宣布获胜者
